# 갈림길 기준 비율 현황(2026-11-08)

자주 일어나는 갈림길부터 기준 비율을 통계로 바꾸기 위한 준비 자료다. 코드는 바꾸지 않고 세기만 했다.

## 어떻게 셌나

- 종류: 기준 비율 묶음(`data/base-shares.json`의 13개 묶음, 192개 갈림길)에서 유형 틀끼리 같은 id를 쓰는 갈림길은 하나로 합쳤다(예: `apply`는 open·portfolio·trade·license 4개 유형이 같이 씀). 상세판 4개(개발자·9급·데이터 분석가·마케터)의 갈림길은 비슷한 것이 있어도 따로 둔다(`진로|id`). 결과 131종류.
- 보기가 2개 이상인 사건만 센다(보기 1개 사건은 선택이 아님). '큰 갈림길'은 세계선을 가르는 내 선택(branch choice), '운 뒤 선택'은 합격 같은 운 사건에 붙은 선택, '작은 선택'은 그 밖의 일상 선택이다.
- 발생 횟수: 인물 3명(예시 인물 김민준·이서연, `scripts/validate.ts`의 평균 인물) × 진로 53개 × 1,000번 × 36개월(2026-12 시작). 예시 인물은 AI 판단 없이 규칙 계산으로 돌렸다(발생 횟수는 거의 같고, 보기 비율만 조금 다를 수 있다).
- 전체 선택 2,016,990번. 그중 큰 갈림길 282,995번(14.0%).
- '지금 base share'는 기준 비율 전체 값(상황 칸 이전의 share). 묶음마다 값이 다르면 범위로 적었다. 1,894개 보기 중 통계는 개발자 '긴 구직 → 공무원 시험' 32.3% 하나뿐이고 나머지는 전부 가정값(평균 인물을 엔진으로 잰 값)이다.
- '시뮬레이션에서 고른 비율'은 위 3명이 실제로 고른 비율.
- 스크립트는 저장소에 넣지 않았다(코드 동결).

원인: 첫 직장이 끝나는 갈림길(번아웃 8개월째부터, 이직 제안 12개월째부터)이 늦고 드물게 나와서, 그만두는 사람의 근속이 길다. 비율을 바꿔도 '언제 나오느냐'는 그대로라 6개 묶음 중 4개는 0.95 한도 안에서 목표에 못 닿는다. 닿는 묶음도 '이직 제안이 오면 91%가 옮김'처럼 현실과 먼 값이 된다. 사건 시기(minTenure·weight)를 바꾸거나 목표를 참고로 내릴지는 팀장 결정을 기다린다.

### 진로별 근속(②): 대기

KOSIS 키는 Vercel Production에 '민감한 값(Encrypted)'으로 들어 있어 `vercel env pull`로 받으면 빈 값이 된다(받은 임시 파일은 지웠고 `.env.local`에는 아무것도 안 넣었다). 키를 `.env.local`에 직접 넣으면 직종·산업 코드 표를 받아 진로별 목표와 코드가 안 맞는 진로 목록을 만든다.
