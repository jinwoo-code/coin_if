# 시연 준비(발표용 노트북 크롬)

배포본 https://coinif.vercel.app 은 무료 키(`GEMINI_TIER=free`)라 AI 호출이 하나씩 4.5초 간격으로 돈다. 무대에서 AI를 새로 부르면 시뮬레이션 하나에 1~2분 걸리고, 하루 한도에 걸리면 'AI 판단 실패'·'AI 문장 대신 기본 문장'이 나온다. 그래서 **발표 전에 캐시를 채우고, 무대에서는 AI를 0번 부르는 것**이 목표다(2026-11-08 리허설: 채울 때 37번, 다시 돌릴 때 0번).

캐시는 그 브라우저의 저장소(localStorage `cr:v10:*`)에 있다. 한 저장소에는 예시 인물 한 명만 들어가므로 **크롬 프로필을 두 개** 쓴다(프로필 A = 김민준, 프로필 B = 이서연). 시크릿 창은 닫으면 지워져서 안 된다.

## 1. 캐시 채우기(발표 전날 또는 당일 아침, 프로필마다 한 번)

무료 키 하루 한도가 남아 있을 때 한다(한 사람에 약 18~19번). 순서대로 열고, 각 화면이 다 나올 때까지 기다린다.

1. 첫 화면 → **'예시로 둘러보기'** → 인물 고르기(A는 김민준, B는 이서연). 이 단계에서만 이 버튼을 누른다.
2. `/simulate`: '분신 판단 진행 (n/8)' 막대 → 타임라인 → '가장 흔한 길을 다 살아봤어요'가 뜰 때까지(약 2분). 판단 8~9번 + 서술·등장인물 6~8번.
3. 타임라인을 연도별로 펼쳐 **'AI 판단 실패'와 'AI 문장 대신 기본 문장'이 하나도 없는지** 본다. 있으면 맨 아래 '다시 살아보기'(↻)를 한 번 누른다(판단은 실패한 칸만 다시 묻고, 서술은 다시 받는다). 그래도 있으면 한도에 걸린 것이니 몇 시간 뒤 다시.
4. '다른 세계선 보기' → `/multiverse`: 요약 카드와 '내가 바꿀 수 있는 것 Top 3'까지 나오게 둔다(Top 3는 브라우저 계산, AI 아님).
5. 다시 `/simulate`로 와서 맨 아래 '진로 한눈에 비교' 표 확인(AI 아님).
6. `/report`: 리포트가 처음 만들어진다(AI 1번). 아래 **'프리미엄 리포트 열기'** 를 눌러 프리미엄까지 연다(AI 1번). 할 일 칸에 '기본 할 일로 채웠어요'가 보이면 새로고침 뒤 한 번 더 연다.
7. 체크인은 **열지 않는다**(아래 '무대 순서'에서 마지막에만).
8. 저장소 백업: 크롬 개발자 도구 콘솔에서
   ```js
   copy(JSON.stringify(localStorage))
   ```
   를 실행하고 메모장에 붙여 `시연-김민준.json`처럼 저장한다. 되살릴 때는 같은 사이트 콘솔에서
   ```js
   Object.entries(JSON.parse(`붙여 넣은 내용`)).forEach(([k, v]) => localStorage.setItem(k, v))
   ```
   뒤 새로고침. 체크인을 한 번 하면 저장소가 바뀌므로 리허설과 본 발표 사이에 이 백업으로 되돌린다.

## 2. '예시로 둘러보기'를 누르면 안 되는 이유

이 버튼은 새 시연을 시작하려고 **저장소를 통째로 지운다**(`app/page.tsx`의 `store.reset()`). 판단·서술·리포트·프리미엄 캐시가 전부 사라져서, 그 자리에서 판단부터 다시 부른다(1~2분 + 한도 소모, 실패 표시 가능). 채운 뒤에는 절대 누르지 않는다. 인물을 바꿀 때는 버튼이 아니라 **크롬 프로필을 바꾼다**.

## 3. 무대에서 들어가는 경로

1. 해당 인물의 크롬 프로필 창에서 https://coinif.vercel.app 을 연다.
2. 첫 화면 머리글 아래 '진행하던 리허설이 있어요' 칸의 **'이어서 하기'** 를 누른다(저장된 결과가 있을 때만 보인다). 진행 상태에 맞는 화면(`/simulate` 등)으로 가고, 저장된 본선을 그대로 열어 AI를 안 부른다.
3. 순서: 결과 요약(`/simulate` 위 카드) → 갈림길 하나 펼치기('자세히' → '보통은 N% → 나는 M%') → '다른 세계선 보기'(갈래 길 지도) → Top 3 → 뒤로 가기로 `/simulate` 맨 아래 '진로 한눈에 비교' 표 → 다시 '다른 세계선 보기' → 맨 아래 '리포트 보기'(`/report`) → `/checkin`(내 정보 → 한 달 체크인 → '시연용: 지금 해 보기' → '예시 답 채우기' → 저장).
4. 무대에서 **누르지 않을 것**: '예시로 둘러보기', 세계선 지도의 '갈림길 바꿔 보기'(캐시가 없어 누를 때마다 AI), 리포트 증거물의 '주제 제안'(AI), 대화(`/talk`)에서 새 질문(AI), 타임라인 '다시 살아보기'(↻).
5. 체크인은 마지막에 한다. 체크인 뒤에는 프로필이 바뀌어 다음에 시뮬레이션을 다시 돌리면 판단을 새로 부른다(그대로 저장된 화면을 보는 건 괜찮다).

## 4. AI 호출 수 확인

- 정확한 수: 배포본이 AI를 부를 때마다 Supabase `usage_logs`에 한 줄이 남는다(로그인 안 한 예시 인물도). 개발 노트북에서
  ```bash
  npx tsx@4.19.2 --tsconfig tsconfig.json --env-file=.env.local scripts/count-ai-calls.ts 2026-11-08T08:00:00Z
  ```
  시각(UTC) 이후 기능별 호출 수가 나온다. 리허설 시작 전에 시각을 적어 두고, 끝난 뒤 **0번**인지 본다. 시각을 빼면 최근 30분. 다른 사람이 같은 배포본을 쓰고 있으면 그 호출도 섞인다.
- 무대 노트북에서 바로 보기: 개발자 도구 → Network → 필터에 `judge` `simulate` `line` `explore` `report` `talk` `evidence` 중 하나라도 요청이 생기면 AI를 부른 것이다. `tokens` `sync` `status` `live` `requirements` `programs`는 AI가 아니다.
- Vercel 로그는 같은 줄이 겹쳐 나와 세는 데 쓰지 않는다.

## 5. 백업 영상으로 넘어가는 기준

영상: `docs/screens/deck/demo.webm`(390×844, 90초, 약 7MB, git에는 없음. 발표 노트북에 따로 복사해 두고 미리 한 번 열어 본다). 김민준 → 이서연 순으로 같은 동선이고, 녹화 중 AI 호출 0번.

다음 중 하나면 **바로** 영상으로 넘어간다.

- 화면을 누르고 **5초** 안에 내용이 안 나온다(빈 화면, '출발 준비 중…', '살아보는 중' 막대가 계속 돎). Top 3도 5초 기준(리허설 노트북에서 약 4초. 더 느린 노트북이면 미리 재 본다).
- **'분신 판단 진행 (n/8)' 막대가 보인다**: 캐시가 없어서 AI를 새로 부르기 시작했다는 뜻이다(1~2분 걸림).
- 'AI 판단 실패' 또는 'AI 문장 대신 기본 문장'이 보인다(한도에 걸림).
- 발표장 네트워크가 끊겼다(캐시가 있어도 리포트의 필요한 것 목록·동기화는 서버를 부른다).

영상 시각(대략): 김민준 결과 요약 0:01, 갈림길 0:10, 지도 0:16, Top 3 0:20, 비교표 0:25, 리포트 0:36, 체크인 0:43 / 이서연 결과 요약 0:45, 갈림길 0:54, 지도 1:00, Top 3 1:04, 비교표 1:09, 리포트 1:20, 체크인 1:27. 끊긴 화면의 시각부터 이어서 튼다.
