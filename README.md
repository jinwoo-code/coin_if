# AI 진로 리허설 (데모)

가보기 전에 미리 살아보는 체험형 AI 진로 컨설팅. 대회 데모용 첫 버전이다.

인터뷰 → 진로 고르기 → 원하는 기간 살아보기(실시간 타임라인) → 그때의 나와 대화 → 비교 리포트·실행 계획까지 한 바퀴가 돈다.

## 1. 실행하기 (처음 한 번)

1. [Node.js](https://nodejs.org) 20 이상을 설치한다.
2. 이 폴더에서 터미널을 열고:
   ```bash
   npm install
   ```
3. AI 키 넣기(없어도 돌아간다):
   - [Google AI Studio](https://aistudio.google.com/apikey)에서 무료 키를 받는다.
   - `.env.example`을 복사해서 `.env.local`을 만들고 `GEMINI_API_KEY=` 뒤에 키를 붙여 넣는다.
   - 키가 없으면 **목업 모드**로 돌아간다. 화면 위에 노란 안내가 뜨고, 미리 써 둔 문장으로 전체 흐름을 볼 수 있다.
4. 실행:
   ```bash
   npm run dev
   ```
   브라우저에서 http://localhost:3000 을 연다. 폰 화면 기준으로 만들었으니 개발자 도구에서 모바일 보기로 보면 좋다.

> `.env.local`은 절대 GitHub에 올리지 않는다(이미 `.gitignore`에 들어 있다).

## 2. 디자인 원칙

- **노선도 모티프**: 진로마다 지하철 노선처럼 색을 준다(개발자 파랑, 공무원 주황, 데이터 분석가 초록, 마케터 보라). 화면의 색은 노선 색뿐이고 나머지는 무채색이다.
- **글꼴**: Pretendard를 앱 안에 직접 넣었다(`pretendard` 패키지). 인터넷이 막혀도 같은 글꼴로 보인다. 한국어 줄바꿈은 단어 단위(`word-break: keep-all`).
- **움직임은 두 곳만**: 첫 화면의 노선이 갈라지는 그림, 타임라인에 노선이 이어지는 순간. '동작 줄이기' 설정을 켠 사람에게는 움직이지 않는다.
- **접근성**: 모든 버튼 44px 이상, 아이콘 버튼 aria-label, 입력창 label, 키보드 포커스 표시, 본문 바로가기 링크.
- **발표용 '예시 인물로 바로 보기'**: 첫 화면에서 인터뷰 없이 바로 시뮬레이션으로 간다(`lib/demo.ts`).

적용한 스킬: frontend-design(Anthropic), UI/UX Pro Max(디자인 시스템·UX 규칙), Vercel web-design-guidelines(코드 검사)·react-best-practices·writing-guidelines.

## 4. 모든 전공: 진로 유형 틀 + 직업 목록

진로는 두 종류다.

- **상세판 4개**(`data/worlds/*.json`): 개발자, 9급 공무원, 공공기관 데이터 분석가, 마케터. 사건을 하나하나 손으로 쓴 진로.
- **유형 틀로 만든 진로 49개**(`data/jobs.ts`): 간호사, 교사, 경찰, 디자이너, 회계, 조리사, 대학원, 창업 등. 한 줄만 쓰면 `lib/archetypes.ts`가 사건·관문·등장인물을 만든다.

| 유형 | 관문 | 예 |
|---|---|---|
| open | 졸업 뒤 매달 일정 확률로 채용(회사 규모별 초임) | 회계, 영업, 엔지니어, 사회복지사 |
| public | 상·하반기 공채(NCS) | 공공기관 사무직 |
| exam | 1년 1~2번 시험 → 첫 근무 | 교사 임용, 경찰, 소방, 세무사 |
| license | 졸업 직전 국가시험 → 면허 → 채용 | 간호사, 물리치료사, 임상병리사 |
| portfolio | 포트폴리오 채용 + 프리랜서 갈림길 | 디자이너, 영상 PD, 웹툰, 통번역 |
| trade | 기능사·현장 채용 + 독립 갈림길 | 정비사, 조리사, 미용사, 트레이너 |
| grad | 대학원 입학(전기·후기) → 연구 생활 → 박사냐 취업이냐 | 대학원 진학 |
| startup | 사업자 등록 → 지원사업 → 매출 자리 잡기 / 접기 | 창업 |

**입력도 전공 무관**: 인터뷰의 스펙은 공통(학교·졸업 시기·학점·어학·자격증 자유 입력·프로젝트/작품/실습·인턴)만 묻고, 진로마다 필요한 준비(코딩, 포트폴리오, 면허, 실습, 체력, 교원 자격 등 15종, `lib/readiness.ts`)는 진로를 고른 뒤에 묻는다. 진로 고르기 화면은 전공 이름으로 관련 진로를 먼저 추천하고, 검색과 계열 필터로 전체를 볼 수 있다.

**졸업 시기**: 정규직 채용은 졸업 뒤부터, 국가시험은 졸업 3개월 전부터 가능하다.

### 진로 하나 추가하는 법(코드 몰라도 됨)

`data/jobs.ts`에 한 줄을 넣는다.

```ts
{ id: "pharma-sales", name: "제약 영업", short: "제약 영업", family: "의약·보건", archetype: "open",
  majors: ["약학", "생명", "화학"], certs: ["운전면허"], readiness: ["service"], hours: 46, tags: ["실적압박"] },
```

- 출처 있는 숫자가 있으면 `facts`에 넣는다. **숫자를 지어내지 않는다.**
- 더 자세히 만들고 싶으면 `data/worlds/`의 상세판처럼 사건을 직접 쓴다(`branch`: 갈림길, `hires`+`tiers`: 취업과 규모별 연봉, `warmup`, `afterGrad`, `tags` 등).
- `npx tsx@4.19.2 --tsconfig tsconfig.json scripts/check-all.ts`로 모든 진로가 돌아가는지, 합격률·만족도가 말이 되는지 표로 확인한다.

## 5. 시뮬레이션이 돌아가는 방식: 멀티버스

**같은 사람이 같은 진로를 한 달 단위로 100번 살아 보고, 갈림길마다 갈라진 세계선을 보여 준다.**

1. **규칙 엔진(`lib/engine.ts`)이 숫자를 전부 정한다.** AI는 숫자에 손대지 않는다.
   - 실제 달력으로 돈다. 다음 달부터 시작하고, 국가직 9급 발표는 5월, 지방직은 7월처럼 실제 시험 달에만 합격·불합격이 난다.
   - 매달 ① 관문(합격·취업)을 내 조건으로 보정한 확률로 굴리고 ② 큰 사건 ③ 일상 ④ 조용한 달 중 하나가 된다.
   - **돈이 실제로 흐른다**: 생활비·집 지원·알바(2026 최저시급 10,320원)·준비 비용이 매달 빠지고, 취업하면 회사 규모별 초임(경총)이 들어온다. 잔고가 0이 되면 '생활비가 떨어짐' 갈림길이 생긴다.
   - **입대**: 미필이면 입력한 시기에 18개월 복무 구간이 끼어든다(회사원은 퇴사, 공무원은 휴직). 입대 전엔 회사 채용 확률을 절반으로 둔다(가정).
   - '나'의 선택은 가치관 순위(8개 중 4개), 성격, 상황 질문 결과(끈기·위험 감수·스트레스 대처)로 정한다. 화면에 이유가 붙는다.
   - 싫다고 고른 일(야근, 민원 등)이 생기면 만족도가 더 깎인다. 일하는 중의 평소 만족도는 그 일이 내 가치관을 얼마나 채우는지로 정한다.
2. **세계선 나무(`lib/multiverse.ts`)**: 100번의 인생을 '인생 방향을 바꾼 갈림길'(합격한 회사 규모, 이직, 퇴사, 전향, 국비 교육 등) 순서로 묶는다. 5% 미만 가지는 묶고, 세계선은 최대 7개.
   - **본선**: AI가 먼저 간 길 = 가장 많이 간 세계선. 시뮬레이션 화면에 이게 나온다.
   - **세계선 열기**: 대표 회차(만족도가 가운데인 회차)를 다시 굴려 AI가 이야기를 입힌다. 같은 시드라 몇 번을 열어도 같은 결과.
   - **갈림길 바꿔 보기**: 선택은 다른 선택지로, 운은 그 순간 한 번 떨어진 것으로 강제하고 100번을 새로 살아 본다.
   - **바꿀 수 있는 것 Top 3**: 자격증·공부 시간·인턴 같은 조건을 하나씩 바꿔 100번 다시 살아 보고, 갈림길별로 고른 쪽에 따라 끝이 어떻게 달랐는지 비교해 효과가 큰 순으로 보여 준다.
3. 무료 키 호출 제한 때문에 AI는 4역씩 묶어서 부른다(3년이면 3번). 다른 세계선을 열 때마다 1번 더.

### 실제 통계와 맞는지 (scripts/validate.ts)

통계와 같은 기준으로 잰다. '평범한 지원자'(모든 개인 배수 ×1: 4년제, 서울, 준비도 질문은 배수 1인 보기, 수험생 하루 8.7시간)로 10년을 400번 살아 보고, **졸업한 달(공무원은 공부 시작)부터 붙은 달까지**, **붙은 사람끼리** 평균을 낸다(통계도 취업 경험자·합격자 기준이라서).

| 진로 | 붙은 사람 평균 | 가운데 값 | 붙은 사람 중 2년 안 | 실제 통계 |
|---|---|---|---|---|
| 공무원(합격 발표 기준) | 22.5개월 | 19개월 | 72% | 합격자 평균 준비 1년 8개월(20개월), 2년 안 73.3% |
| 개발자 | 11.9개월 | 8개월 | 89% | 졸업 후 첫 취업까지 평균 11.2개월(전체 청년, 모든 일자리) |
| 마케터 | 13.0개월 | 10개월 | 87% | 같음 |
| 데이터 분석가 | 23.0개월 | 21개월 | 61% | 비교할 통계 없음 |

- 상시 채용 진로 중 기본 확률이 보통(0.065~0.08)인 진로들의 붙은 사람 평균은 13.0개월이다. 통계는 아무 일자리나 첫 취업이고 우리는 그 직업에 붙기까지라서 조금 더 걸리는 게 자연스럽다고 보고 그대로 둔다.
- 2026-10-30에 검증 방법을 고쳤다. 예전에는 졸업 12개월 전 재학생이 준비도 질문에 답하지 않은 채(답이 없으면 한 단계 낮은 보기로 본다), 전문대·경기도 조건으로 시작부터 세서 개발자가 21개월로 나왔다. 엔진이 아니라 재는 방법이 문제였다.
- 같은 날 공무원을 다시 보정했다. 예전에는 3년만 돌려서 3년 넘게 걸린 합격자가 빠져 통계와 맞아 보였고, 10년을 돌리면 합격자 평균이 36.6개월이었다. '계속할지 고민' 갈림길을 1·2·3년차마다 두고 시험 한 번의 합격 확률을 0.16→0.25, 준비 효과(`warmup`)를 16→12개월로 바꿨다.
- **준비생 전체 중 결국 붙는 비율(지금 10년 안 79%)은 공개 통계가 없어서 검증되지 않았다.** 화면 근거 자료에도 가정값으로 적었다. 경쟁률·응시자 수를 모으면 이 부분을 맞출 수 있다.
- 교사·경찰·소방·세무사 같은 다른 시험형 진로는 비교할 합격자 통계가 없어서 보정하지 않았다.
- 개인 조건 배수(자격증 ×1.12 같은 것)도 가정값이다. 심사에서 물으면 "공개 통계로 평균을 맞췄고, 개인 배수는 가정이며 화면에 그대로 공개한다"고 답한다.

### 근거 자료

진로마다 `facts`에 실제 출처가 있는 숫자가 들어 있고, 세계선 지도 화면의 '이 세계를 만든 근거 자료'에 링크와 함께 나온다(인사혁신처 경쟁률·봉급표, 통계청 청년층 부가조사, 경총 초임, 한국행정연구원 공직생활실태조사, 공무원연금공단 저연차 퇴직, 인크루트 공공기관 연봉 등). 고용24 응답을 확인하면 `data/jobdata/README.md` 순서대로 늘린다.

## 6. 신청서 대비 지금 단순하게 만든 부분

솔직하게 알고 있어야 심사 질문에 답할 수 있다.

- **DB 없음**: 진행 상황은 브라우저(localStorage)에만 저장된다. 상담사 대시보드, 체크인 알림 발송은 아직 없다(체크인은 캘린더 파일 다운로드로 대신).
- **다중 에이전트 단순화**: 등장인물 반응을 에이전트마다 따로 부르지 않고, 한 번의 AI 호출 안에서 서술한다. 비용과 속도 때문이다.
- **유형 틀 진로는 상세판보다 얕다**: 사건이 유형 공통이라 직업마다 디테일이 부족하다. 직업별 채용 확률(`hazard`)·시험 합격률도 대부분 가정값이다. 현직자 인터뷰와 API로 하나씩 상세판으로 올린다.
- **교사·경찰·소방·세무사 초봉**은 출처가 없어 9급 초임 수준으로 둔 가정값이다(화면에 표시됨).
- **개인 배수는 가정값**: 평균 확률은 공개 통계에 맞췄지만, 자격증·지역·학력 같은 개인 조건 배수는 근거 데이터가 없어 우리가 정했다(5장).
- **흥미 검사**: 커리어넷 키가 있으면 커리어넷 직업흥미검사(공인)를 쓴다. 키가 없거나 호출이 실패하면 직접 쓴 간이 24문항으로 대신한다(표준화 검사 아님). 커리어넷은 심리검사에만 쓰고, 직업·학과 정보는 고용24로 받는다.
- **성격 50문항 번역**: IPIP 공개 문항을 우리가 옮겼다(공식 한국어판 아님).
- **FastAPI·Redis·pgvector 없음**: Next.js 하나로 만들었다. 데모 단계에서는 이게 더 빠르고 안정적이다.

## 7. 배포(발표 때 폰으로 보여 주기)

1. 이 폴더를 GitHub 저장소에 올린다. `.env.local`은 `.gitignore`에 있어서 올라가지 않는다(`git status`에 안 보이는지 한 번 더 확인).
2. [Vercel](https://vercel.com)에 GitHub로 로그인 → Add New Project → 저장소 선택.
3. Environment Variables에 `.env.local`의 값을 그대로 넣는다(Production·Preview 둘 다).
   - `GEMINI_API_KEY` (없으면 목업 모드). `GEMINI_FAST_MODEL`, `GEMINI_SMART_MODEL`은 넣지 않으면 기본값.
   - `WORK24_KEY_WANTED`, `WORK24_KEY_TRAINING`, `WORK24_KEY_MAJOR`, `WORK24_KEY_PROGRAM`, `WORK24_KEY_CODE`, `WORK24_KEY_DUTY`, `WORK24_KEY_JOB`
   - `CAREERNET_KEY`
4. Deploy. 나온 주소를 폰으로 열면 된다.

설정은 코드에 들어 있다.
- `vercel.json`: 함수 지역을 `icn1`(서울)로 고정. 사용자와 가깝고, 고용24·커리어넷 같은 국내 공공 API가 해외 IP를 막는 경우를 피한다.
- `app/api/simulate/route.ts`: `maxDuration = 300`(초). 100번 돌리기 + AI 문장 스트리밍이 길어질 수 있어서다. Hobby 플랜은 Fluid compute(새 프로젝트 기본값)가 켜져 있어야 300초까지 된다.

### 배포 후 확인 체크리스트

- [ ] Settings → Functions에서 Fluid compute가 켜져 있고, 함수 지역이 Seoul(icn1)인지
- [ ] `/api/status`가 `"llm": true`인지(키를 안 넣었으면 `false` = 목업 모드)
- [ ] 첫 화면 → '예시 인물로 바로 보기' → `/simulate`가 끝까지 흘러나오는지(중간에 끊기면 Logs에서 실행 시간 확인)
- [ ] `/multiverse`의 '지금 현실에서는'에 실제 공고가 뜨는지. 안 뜨면 Logs에서 `[고용24 실패]` 검색
- [ ] `/deepen` → '가치관 28' 탭에 문항이 뜨고, 제출하면 '커리어넷 결과지 보기'가 열리는지. 안 되면 Logs에서 `[커리어넷 실패]` 검색
- [ ] `/report`에 고용센터 프로그램이 뜨는지, `/talk` 대화가 되는지
- [ ] Logs의 `[토큰]` 줄로 한 번 돌릴 때 드는 토큰 확인
- [ ] 브라우저 개발자 도구 Network·페이지 소스에서 키 문자열이 안 보이는지(키는 서버에만 있어야 한다)
- [ ] 실제 폰(데이터·와이파이 둘 다)으로 열어 보기. 홈 화면에 추가해 두면 발표 때 바로 열 수 있다

발표장 와이파이가 불안하면 키를 빼고 목업 모드로 시연하는 게 안전하다. 목업 모드도 흐름은 똑같이 돈다.
